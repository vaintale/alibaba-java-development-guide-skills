# 文档版本守卫（md-version-guard）

> 项目文档的两个老问题：**不知道哪一版最新**，**不知道这次改了什么**。
> 两条硬规则解决：版本号写进文件名，变更记录写进第一屏。

---

## 一、规则

### 1. 文件名带版本号

```
用户中心设计V1.0.md → 用户中心设计V1.1.md → … → 用户中心设计V1.9.md → V2.0
```

- 大写 `V`，紧贴数字，不留空格
- 每次编辑 **+0.1**；1.9 之后进位到 2.0（不存在 V1.10）
- 不写「最终版」「最新版」，日期不写进文件名

### 2. 文档第一屏是变更记录

```markdown
# 用户中心设计

| 版本 | 日期 | 变更人 | 类型 | 变更内容 |
|---|---|---|---|---|
| V1.1 | 2026-11-13 | AI | 修订 | 登录态过期改为滑动窗口，按评审意见调整时序图第 3 步 |
| V1.0 | 2026-11-12 | AI | 初版 | 创建文档 |
```

最新在最上面；类型只有 `初版 / 新增 / 修订 / 纠错` 四种；内容写「改了什么 + 为什么」。

## 二、每次更新做的事

```
定位最新版 → 读全文与变更表 → 改内容 → 表里插一行 → 原地改名 → grep 更新引用
```

最后一步不能省：改名后别处的链接会变成死链。

## 三、目录结构

```
md-version-guard/
├── SKILL.md                 # 主协议：两条规则 / 六步更新 / 异常处理 / 反模式
├── README.md                # 本文件
└── references/
    ├── naming.md            # 版本号解析、进位、非法写法、找最新版命令
    ├── changelog.md         # 变更表列定义、类型判定、好坏对照
    └── workflow.md          # 新建 / 更新 / 纳入管理 / 冲突 / 多文档 的操作序列
```

## 四、安装

**WorkBuddy**：把 `md-version-guard/` 放到 `~/.workbuddy/skills/` 下。

**Claude Code**：

```bash
cp -r md-version-guard ~/.claude/skills/
```

## 五、使用

不需要手动调用，说需求即可：

| 你说 | 它会做 |
|---|---|
| 「写一份订单重构方案」 | 生成 `订单重构方案V1.0.md`，带首行变更记录 |
| 「把方案里的拆分粒度改成两个服务」 | 改内容 → 表里加 V1.1 → 改名 → 查引用 |
| 「这份设计文档没有版本号」 | 加变更表、改名 V1.0、更新引用，并说明「只改名没改内容」 |
| 「文件名别动，别人在引用」 | 只记变更表，不改名，交付时标注 |

## 六、边界

- **只管 `.md`**。docx、xlsx、pdf 不在范围内——那些文件的版本与修订记录由对应工具处理。
- **不管 README / CHANGELOG / LICENSE / CONTRIBUTING**。改这些文件会破坏仓库约定（GitHub 只认 `README.md`）。
- **不自动删除历史版本**。发现目录里有 V1.2、V1.3 并存时，以高版本为准继续改，只提示归档。
- **旧内容不保留副本**。历史靠变更表（人看）+ git（机器看），目录里永远只有一个当前版本。

## 七、与 git 的关系

变更表是摘要，git 是底稿。两者不冲突：

```bash
git mv 用户中心设计V1.2.md 用户中心设计V1.3.md
```

用 `git mv` 而不是 `mv`，git 才能识别为重命名，历史可追。
