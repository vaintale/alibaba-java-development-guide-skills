# 改后自检与 diff 审查

> 编辑事故大多不是「不会写代码」，而是「改多了」或「没验证」。这份清单用来在交付前把这两类问题拦住。

---

## 1. 先看 diff 的形状

执行 `git diff --stat`，判断改动规模是否符合预期：

| 观察 | 判断 |
|---|---|
| 只改了 1~2 个文件、几十行 | 正常，符合 R1~R3 |
| 改了几百行，但任务只是「加个参数」 | ❌ 扩散了，回退重来 |
| 出现未预料到的文件（`pom.xml`、配置文件、其他模块） | ❌ 检查是否误触或工具自动改写 |
| 整个文件每行都变红又变绿 | ❌ 行尾或缩进被改了，用 `git diff -w` 确认 |

`git diff -w`（忽略空白差异）之后若 diff 大幅缩小，说明做了无意义的格式改动，必须还原。

---

## 2. diff 噪声清单（出现即还原）

| 现象 | 为什么有害 | 怎么发现 |
|---|---|---|
| 整文件缩进变化、tab↔空格 | 掩盖真实改动，review 无法进行 | `git diff -w` 后差异消失 |
| 行尾 CRLF ↔ LF 变化 | 全文件变红，合并冲突 | `git diff --ignore-cr-at-eol` |
| `import` 重排或删除 | 静态初始化顺序可能变化；冲突源 | 看 diff 头部 |
| 重命名本次没改到的变量/方法 | 无收益，扩大影响面 | 搜索重命名标识符的调用点 |
| `for` 改 `stream`、匿名类改 lambda | 纯风格，与任务无关 | 肉眼 |
| 改写无关注释、删 `@author` | 丢失历史信息 | 肉眼 |
| 方法在类中顺序变化 | 无意义的大 diff | 肉眼 |
| 日志文案/格式微调 | 可能破坏依赖日志关键字的告警规则（契约项 8） | 看 `log.` 行 |

**唯一例外**：任务本身就是「格式化」「统一风格」「重构」。这时要在报告里写明范围，并单独提交。

---

## 3. 结构性自检

- [ ] diff 里每个 hunk 都能对应到任务需求或本次触碰范围内的红线修复
- [ ] 新增/修改的方法有注释说明「做什么、为什么」，公共方法有 `@param` / `@return`
- [ ] 异常路径完整：catch 有处理动作，不吞、不只打日志就继续
- [ ] 边界值：空集合、null、0、负数、超长字符串、并发
- [ ] 事务：拆分后仍在同一事务内的操作没有跨方法失效
- [ ] 资源：新增的流/连接/锁有释放路径
- [ ] 日志：关键分支有日志、带业务标识、不含敏感信息
- [ ] 没有留下 `TODO` / `FIXME` / `System.out.println` / 调试断点

---

## 4. 编译与测试

```bash
# Maven（离线优先，避免联网下载）
mvn -q -o compile
mvn -q -o test -Dtest=OrderServiceTest

# Gradle
./gradlew compileJava --offline
./gradlew test --tests "*OrderServiceTest" --offline
```

- 编译不过：先修到通过再交付。若因缺少私有依赖无法编译，在报告里明确写「未编译：缺少 xxx 依赖」。
- 测试失败：判断是本次改动导致，还是既有失败。既有失败要在报告里注明「改动前已失败」。
- **禁止**在没有执行的情况下写「已验证通过」。没跑就写「未验证」并说明原因。

---

## 5. 改动确实很大时（R4 / R5）

不要一次性甩出一个几百行的 diff。按下面的顺序做：

1. **先出方案**：改动文件清单、每个文件改什么、影响哪些调用方、怎么回滚、怎么验证。等确认后再动手。
2. **重构与功能分开**：「把方法拆小」和「加新功能」是两个提交，混在一起无法 review，也无法回滚。
3. **每一步可编译**：不要留下「改到一半编译不过」的中间态。
4. **兼容式改造**：需要替换公共方法时，先新增新方法 → 旧方法委托新方法并标 `@Deprecated` → 调用方逐个迁移 → 最后删除旧方法。不要一步到位改签名。
5. **灰度点写清楚**：新逻辑用什么开关控制、怎么回退。

---

## 6. 交付前 60 秒清单

```
□ git diff --stat 的规模符合任务预期
□ git diff -w 没有隐藏的格式改动
□ 编译通过（或已说明未验证原因）
□ 相关测试通过（或已说明既有失败）
□ 红线 §5 表逐条对过一遍
□ 报告四段写全：改了什么 / 依据 / 验证 / 没做与风险
```
